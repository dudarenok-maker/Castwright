**A cast-first, hardening release.** Confirming a cast now lands you with your characters instead of the manuscript, and a new pre-flight check stops a book from generating with an undesigned Qwen voice rather than failing loudly mid-render. Everything else tightens what's already there: a Mac or graphics-card-free machine now runs multiple voices at full speed instead of queueing behind a small-GPU habit, a chapter stuck behind a confirmed fallback actually starts, and a run of casting, mobile, and LAN-access fixes round out the polish.

---

## ✨ Headline features

### 🎭 Cast-first landing + a pre-flight voice-readiness gate (new) — fe-46
Confirming a cast now takes you straight to your characters, and starting a render checks every one of them has a voice before committing to a generic stand-in.

- **`confirmCast` now lands on the Cast view, not Manuscript** — the flow
  becomes confirm → Cast → Manuscript → Generate, with a new "Continue to
  manuscript" CTA on the Cast view's header action row (#1278).
- **A pre-flight voice-readiness gate** opens instead of the tier prompt when
  `startGenerationFlow` finds a speaking Qwen character with no designed
  voice: lists them in talk-time order, offers "Design full cast" as the
  primary action and "Proceed anyway — generic Kokoro fallback voices" for
  English books, and hard-blocks with no proceed affordance for non-English
  books (#1278).
- **New reusable selectors** — `src/store/voice-readiness-selectors.ts`
  (`selectUndesignedQwenCharacters`, sharing the cast view's exact
  `needsVoiceIds` semantics via `resolveVoiceStatus`) and `src/lib/cast-sort.ts`
  (`compareCastRows`, extracted out of `views/cast.tsx`).
  `EnqueueInput`/`QueueEntry` gain an optional per-entry `fallbackConfirmed`
  flag, stamped at enqueue by the proceed-anyway path so the per-chapter
  `awaiting_fallback_confirm` gate doesn't re-prompt for that run's fresh
  chapters — later enqueues still get the per-chapter backstop (#1278).

## 🔊 Generation quality & reliability

- **The GPU-arbitration semaphore no longer serialises multi-engine generation on hardware with no VRAM to protect.** It was charging VRAM-budget tokens for kokoro/qwen/coqui synth and Qwen VoiceDesign calls even when the engine was confirmed running on CPU or Apple Silicon (MPS) — a new per-engine device cache (fed from the sidecar's existing per-engine `devices` health-poll data) now gates these semaphore acquires, and the pre-load analyzer-eviction guard, on the engine's actual runtime device rather than a config-knob guess. Also fixes Coqui's own `auto` device resolution, which had no MPS branch (unlike Qwen's), so it always ran on CPU on Apple Silicon even when MPS was available (#1324).
- **A chapter confirmed past the loud Qwen→Kokoro fallback gate could get permanently stuck at "line 0" and never dispatch.** `queue-dispatcher-middleware`'s reconcile was reading the Redux queue slice's `status` field to decide whether a just-closed stream was a park (`awaiting_confirm`) or a real completion — but nothing synchronizes that field with the `chapter_awaiting_fallback_confirm` SSE tick, so the field could still read the entry's pre-park `in_progress` status when the reconcile ran. That misread the park as a completion, which poisoned the dispatcher's in-memory de-dupe set for that entry — since the entry never actually leaves the live queue, nothing ever cleared the poison, so even after the user confirmed the fallback the entry was silently skipped forever. The reconcile now asks the stream runner directly (which already tracks this unambiguously off the SSE tick) instead of the racy Redux copy (#1284). Also memoized `selectQueueByBook`, an unmemoized selector that allocated a fresh array on every call and forced the queue modal to re-render on every store dispatch — a confirmed contributing factor to a `GenerationView` crash captured during the same investigation (#1285).
- **A chapter's binary `audio.mp3` could 500 with an empty body and nothing in the logs, even though the file existed on disk and the JSON metadata endpoint for the same chapter served fine.** `chapter-audio.ts`'s `res.sendFile` call runs through Express's `send` module, which treats any ancestor path segment starting with `.` (e.g. a workspace nested under a `.claude/worktrees/<name>/castwright-workspace` checkout — exactly how Claude Code's own parallel-agent worktrees are laid out) as a "dotfile" and, under the default `dotfiles:'ignore'` policy, silently turns the request into a 404-shaped internal error; the route's catch-all then flattened that into an opaque 500 regardless of the real error. `audio.path` is fully server-computed from a validated bookId/chapterId lookup, never client input, so the dotfile guard was a pure false positive here — now passes `dotfiles: 'allow'` and logs the real error message/status so a genuine future failure isn't silent (#1290).
- **Title-narration synth call now wrapped in per-call timeout** (#1247, srv-51) — matches the defensive timeout protection added to every other synth call site, closing a gap where a wedged title narration could stall a chapter. No user-visible change under normal operation; defensive only.
- **A sidecar restart forced every 1.7B voice to be re-derived from scratch, even when it didn't need to be.** `_load_voice_prompt_17b` (`server/tts-sidecar/main.py`) only checked its in-memory prompt cache before re-deriving a voice's native 1.7B clone prompt via a GPU decode + `create_voice_clone_prompt` call — it never read back the `<voice>__1.7b.pt` file a prior process had already persisted to disk, despite the function's own docstring claiming a restart "skips the derivation step". A chapter with several speakers right after a sidecar restart (soft-recycle, or a genuine crash) could stack multiple full re-derivations in a short window — a contributing factor to the still-open side-11 host-memory leak's recycle storms. Now checks the on-disk `.pt` file first (Refs #399).
- **An overnight generation could go silently asleep for hours.** Windows put the machine into Modern Standby mid-run (Idle Timeout, ~3 minutes after the run started) even though the AC power-plan sleep setting read "never" — something outside the app's control (a vendor power utility, or being on battery at the time) can override that setting. The server now holds `ES_SYSTEM_REQUIRED` (via a spawned `scripts/lib/prevent-sleep.ps1` helper) for as long as any chapter is in flight, across every book, hooked onto the existing `registerJob`/`deregisterJob` tracker in `generation.ts` — the display still dims/turns off normally, only system sleep is suppressed. New `PREVENT_SLEEP_DURING_GENERATION` env toggle (default on, Windows-only). See [plan 242](features/archive/242-sleep-prevention-during-generation.md).
- **The per-regenerate Qwen quality-tier override (plan 229, #4) was a silent no-op on any already-cast book.** `routeFor()` (`server/src/tts/synthesise-chapter.ts`) let a character's stored `ttsModelKey` win outright over the run's `modelKey` — since fs-56 stamps every cast member with a tier once cast, picking "Qwen3-TTS 1.7B" in the Regenerate modal's Model picker rendered every character at whatever tier cast.json already had, not the chosen one. New `higherQwenTier()` (`server/src/tts/model-keys.ts`) resolves the two instead of "character always wins", so the per-character field only ever elevates a character above the run/regenerate default, never downgrades one below it. An independent review of the fix caught the same stale-precedence bug in `generation.ts`'s run-start VRAM-hygiene precompute (it decides which resident Qwen tier(s) to evict before chapter 1) — left on the old logic, it would have evicted the 1.7B tier `routeFor` was about to request, forcing a cold mid-run reload on chapter 1 anyway. Both sites now share one `computeUsedQwenTiers()` helper (`server/src/tts/per-character-engine.ts`) so they can't drift apart again (#1370, Closes #1369).
- **A misfiring VRAM guard was hard-recycling the sidecar mid-chapter every few minutes on single-GPU boxes — the direct cause of the 2026-07-06 recycle storms that paused the queue.** The per-card `driver_free_floor` check (designed as the ONLY OOM guard for ORT/CT2-only cards, whose VRAM is invisible to torch's reserved metric) was applied to *every* card, including the one torch actively manages — where a routine 1.7B batch peak (torch reserved ~6 GB + CUDA context + display compositor on an 8 GB laptop card) legitimately leaves under the 1024 MB floor. Each false trip drained and killed the sidecar mid-chapter; two on one chapter tripped the recycle-storm breaker and paused the whole generation queue. The floor now skips any card with ≥256 MB torch-reserved (its OOM protection remains the per-card reserved-VRAM ceiling, unchanged); torch-unreadable cards keep the floor. The trip log also now prints the actual free-MB reading and floor value (previously `0MB crossed ... 0MB`, which hid that every recycle that day was the same guard).
- **Editing a chapter's manuscript could permanently overwrite it with the app's built-in demo text.** The manuscript slice defaulted its `sentences` to the demo fixture (as both its initial state and its `reset()` value), and `ManuscriptView` fell back to the same fixture whenever the sentences prop was momentarily null (e.g. mid-hydration); combined with debounced autosave persisting the full array on any edit, this baked the demo fixture into a real book's `manuscript-edits.json` — confirmed on two real books. Both defaults now correctly resolve to empty, and the server-side manuscript save additionally shape-validates the patch and refuses one that would wipe an already-analysed manuscript to zero sentences (#1356).

## 🎙️ Voice design & casting

- **A non-English book's voice library never actually hid ineligible voices in the Cast view, despite the filter shipping and being unit-tested in 1.10.0 (`fs-41`, #666).** `VoiceLibraryPanel`'s own `bookLanguage` filter (`voice-library-panel.tsx`) was correct in isolation, but `CastView` never passed it `bookLanguage` at either of its two render sites (the desktop aside and the mobile/tablet bottom sheet) — even though `CastView` already receives that prop and uses it elsewhere (the Qwen auto-load banner). The filter was live, tested, and completely dead in the real cast flow. Now wired through both sites, with a regression test asserting a Russian book's panel actually hides English-only voices.
- **Non-English chapters with an undesigned voice now fail immediately and clearly** (#1263) — previously they parked with a "Render anyway" offer that could never actually succeed on a non-English book, leading to a confirm→fail loop. The failure now names every affected character up front, persists so a reload shows "Failed" (not "Queued"), surfaces an immediate toast, and — since it's a deterministic per-book cast-configuration issue, not a systemic fault — no longer risks pausing the entire cross-book generation queue.
- **The voice-drift report modal could crash outright for a character whose color is a raw hex string rather than a named `CHAR_COLORS` slot key.** `DriftGroupCard` read `CHAR_COLORS[colorKey].hex` with no fallback, so a miss threw and the app's top-level ErrorBoundary replaced the whole page. Now falls back to `CHAR_COLORS.narrator`, matching the same guard already used in four other places (#1344).

## ⚙️ Settings, setup & LAN access

- **Hardware guidance reconciled with castwright.ai.** The About page and the "Will it run on my machine?" device panel now say a 6 GB GPU gets you started and 8 GB is the sweet spot, matching the FAQ on the website (#1274).
- **`castwright.local` now works with no port typed, and the LAN certificate can be regenerated from inside the app.** A new port-443 forwarder relays to the existing `:8443` LAN HTTPS server; a "Regenerate certificate" button in the LAN Access card hot-swaps a fresh mkcert certificate into the running server with no restart. Also fixes a live CSRF-origin bug where mutating requests via `castwright.local`/`castwright.dev.local` 403'd (#1296).

## 📱 Mobile & responsive polish

- **The Books view could overflow horizontally on a phone.** `WorkspacePathRow`'s workspace-path `<span>` (`src/components/library/library-chrome.tsx`) carried a fixed `max-w-[520px]` with no responsive breakpoint, so a realistic (long) workspace path forced the page 232px wider than a 390px phone viewport instead of truncating with an ellipsis. Now caps at `calc(100vw-10rem)` below the `sm:` breakpoint, reverting to the original 520px cap at tablet/desktop widths (#1298).
- **The Books view still overflowed horizontally by ~2px on a phone even with a short workspace path.** The filter-pills + Cards/Table view-mode-toggle row in `library-chrome.tsx` was the only flex row in that component missing `flex-wrap`, so at 390px width the two non-wrapping children's combined intrinsic width narrowly exceeded the available space. Added `flex-wrap` to match every sibling row in the same component; since `justify-between` left-aligns a lone item once it wraps to its own line, the toggle also switched from `justify-between` to `ml-auto` so it stays right-anchored whether or not it wraps (#1325).

## 🏗️ Under the hood

- **The Admin console's two watch tables (Generation throughput, Resource trends) had their column headers drift out of alignment with the data below them, worst on the Resource trends VRAM column.** Both tables' grid-column templates ended their last track in `auto`, and since each table's sticky header and every data row render as their OWN independent CSS grid container, `auto` sizes to that container's own content — the header's short label (e.g. "VRAM") vs. a row's much wider value ("23.9 / 24.0 GB") — which shifted every later column out of line with its header by however much those two widths differed. Every column now gets an explicit width, closing the gap for good; the regression lives in a new Playwright assertion since a jsdom string-equality test on the class name can't catch a layout-only drift. Resource trends also gains the same per-chapter "QA" (re-record RTF) column the throughput table already had, immediately before RTF.
- **`openapi.yaml`'s `QueueEnqueueRequest` now matches the real `/api/queue/enqueue` request shape** (#1264, srv-55) — was documented as `{ bookId, chapterIds[] }`; the route actually takes a per-entry `entries[]` array (new `QueueEnqueueEntry` schema: `id`, `bookId`, `chapterId`, `scope`, optional `characterId`/`modelKey`/`addedAt`/`fallbackConfirmed`). `src/lib/api-types.ts` regenerated to match. Docs/contract fix only — no runtime behaviour change.
- **`resource-telemetry.test.ts` could fail under a loaded full test run.** Two contributing defects: the boot-time workspace-override resolver read a stale hardcoded legacy settings path instead of the shared, env-redirectable one, so a stray legacy file could silently defeat a test's `WORKSPACE_DIR` isolation; and the suite's cap-rotation test's heavier real-fs I/O could blow the default test timeout under pool contention, leaving an abandoned background write that corrupted the next two tests in the file. Fixed the resolver and gave that one test the same kind of timeout headroom already used elsewhere for slow I/O under contention (#1337).
- **`npm run wiki:sync` now refuses to silently publish a bulk page deletion.** The wiki mirror step deletes every page not present in `docs/wiki/` before pushing, with no review gate in between — GitHub wikis have no PR/CI of their own to catch a mistake first. The sync now prints an added/changed/removed summary and refuses to push past 3 removed pages unless re-run with `--allow-deletes` (#1343).
- **Quality Gate wiki page ships real screenshots and documents the content-QA gate for the first time.** `The-Quality-Gate.md` now covers the acoustic gate alongside the ASR content-QA gate (previously undocumented), with real screenshots for a flagged Suspect chapter, the voice-drift report, and the mini-player preview surface — replacing the placeholder note tracked as #1286. (PR #1348)
- **Model Manager gets its own wiki page, and Advanced Settings finally gets full documentation.** `Admin-and-Model-Manager.md` split into `Admin.md` + `Model-Manager.md`, with `Model-Manager.md` gaining full per-knob detail and a screenshot for every one of its 7 settings sections (Device, Installed models, Defaults for new books, Two-model analyzer split, Voice engine, Server configuration, Install/update analyzer). `Advanced-Settings.md` rewritten so all 11 knob groups (97 knobs total) get their own per-section screenshot + full table, replacing the old single-screenshot placeholder (#1319). Also closes all 11 remaining wiki interaction-state screenshot gaps — modals, drawers, mid-action/loading states — tracked in #1318, and adds a `strict: true` mode to the marketing screenshot capture harness (`e2e/marketing/scenes.ts`/`capture.spec.ts`) so a new scene fails loudly on a missed interaction instead of silently shipping the wrong screenshot. (PR #1360)
- **The tier modal's 1.7B eligibility guard had its own inline "has a designed voice" check** — a third parallel definition alongside the cast view's `needsVoiceIds` and fe-46's `selectUndesignedQwenCharacters`. `StartGenerationModal`'s confirm path in `layout.tsx` now derives eligibility from that shared selector instead of re-implementing the check, so "has a designed voice" has exactly one definition. Pure refactor, no behaviour change; a new `layout.test.tsx` case pins that the modal and the voice-readiness gate agree on the same designed-set for a mixed cast (fe-47, #1292).
- **`lan-port-forwarder.test.ts`'s "round 5 (Finding 2)" tests could intermittently crash with an uncaught ECONNRESET**, observed once on macOS CI. Both tests synchronized on the client socket's own `'connect'` event as a proxy for the server's connection handler having attached its upstream error listener — an ordering Node doesn't actually guarantee. `startPortForwarder` now exposes a test-only `onConnection` hook, fired once listeners are attached, and the tests synchronize on that instead of the client-connect proxy (#1351).
