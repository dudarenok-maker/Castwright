# fs-38 Wave 3c — XTTS voice clone Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a cloned voice render on the Coqui XTTS v2 engine as well as Qwen — and close the four upstream paths that currently **delete or launder the clone marker before any resolver can see it**, which today let a cloned voice render as a stranger on a non-English book.

**Architecture:** The clone identity lives in the voice-library entry (`master.wav` + consent). 3c adds a **second derivable artifact** for that identity — `voices/xtts/xtts-<uuid>.pt` (gpt conditioning latents + speaker embedding) — produced by a new sidecar route `POST /xtts/clone-voice` from the same PCM the Qwen route consumes. Everything downstream becomes **engine-parametric** rather than Qwen-hardcoded. Derivation is **lazy**: assignment writes both clone-capable engine slots, and whichever engine a chapter routes to gets its artifact derived by the 3b2 pre-pass — now partitioned by engine so Qwen and Coqui are never forced co-resident.

**Tech Stack:** Python 3.12 sidecar (FastAPI, coqui-tts 0.27.5, torch), Node 20 + TypeScript server (Express, Vitest), React 18 + RTK frontend, Playwright e2e, pytest.

**Review provenance.** This plan was revised after two independent Opus passes — an assumption-checker (verdict on the first draft: *"not safe to execute as written"*, 7 Criticals) and an adversarial substitution hunt (4 Criticals, 6 Highs). Findings are cited inline as `[AC-n]` and `[ADV-n]` so an implementer can trace any requirement back to the evidence. **Both passes independently found four of the same defects** — the mock layer being unable to fail, the latents-cache interleaving, the audition path disagreeing with the render, and D-E breaking designed voices.

## Global Constraints

Every task's requirements implicitly include this section.

- **`TtsEngine` has no `'xtts'` value.** The engine is `'coqui'` (`server/src/tts/model-keys.ts:18`). `xtts` is **only** (a) the manifest slot key `engines.xtts`, (b) the artifact dir `voices/xtts/`, (c) the storage-key prefix `xtts-<uuid>`. Never add `'xtts'` to `TtsEngine`; never route on `engine === 'xtts'`.
- **The headline invariant:** a cloned-provenance voice either renders as itself or fails loud. Never substituted — not by `FALLBACK_SPEAKER`, not by `applyQwenFallback`, not by the coqui profile catalog, **and not by having its marker deleted upstream** (Phase 0).
- **`provenance === 'cloned'` is the gate, not `libraryUuid`.** A library voice can be `designed` or `imported`; those must keep their existing behaviour. Every new branch that reads `libraryUuid` must also test provenance. `[AC-C5] [ADV-H3]`
- **OpenAPI is the type source of truth.** `VoiceLibraryEngines.xtts` already exists at `openapi.yaml:5087-5093` with `coquiVersion` + `modelId` (NOT `baseModel`). Wire changes go in `openapi.yaml` then `npm run openapi:types`. **Never hand-edit `src/lib/api-types.ts`.**
- `server/src/workspace/voice-library.ts:23-33` is a **manual mirror** of that schema — keep field names identical.
- **User-facing copy names the engine "Coqui XTTS v2"**; the blessed short label is **`Coqui`** (`src/lib/tts-models.ts:146-152`). Never bare "XTTS" in UI copy — including status chips. `[AC-I8]`
- **No hex colour literals in components.** **Touch targets ≥44×44** via `min-h-[44px] fine-pointer:min-h-0` (never `sm:min-h-0`).
- Everything stays behind `voices.library.enabled` (`server/src/config/registry.ts:644-653`). No new feature flag. `XTTS_VOICES_DIR` is a derived spawn env like `QWEN_VOICES_DIR`, not a user knob — no registry entry. Any *other* new env var needs one.
- **Sidecar tests run without GPU or weights.** Use `sys.modules` injection (`tests/test_runtime_wiring.py:53-190`) or fixture reuse (`tests/test_qwen_clone_voice.py:1-31`). Use **bare `TestClient(main.app)`**, never `with TestClient(...)` — the context manager fires six startup handlers against the fake torch. `[AC-I5]`
- **`vi.resetModules()` footgun:** never assert `instanceof` on a statically-imported class in a file calling `vi.resetModules()`. Dynamic-import from the same epoch, or use DI overrides (`synthesise-chapter-cloned-resolver-real-deps.test.ts:1-24`).
- Commit convention `<type>(<scope>): <subject>`; scopes `server`/`frontend`/`sidecar`/`docs`/`e2e`/`scripts`. Branch `feat/fs38-wave3c-xtts`. PR links `Closes #624` plus the Phase-0 bug issues.

# Phase 0 — Preserve the clone marker (live substitution bugs)

**These four defects exist in shipped code today.** They are not 3c risks. Each deletes or launders `provenance:'cloned'` *before* any resolver runs, so every guard 3b2 shipped and every guard 3c adds is inert against them. Phase 0 lands first: building new safety on ground that can be pulled away is pointless.

Each task files/links a `bug` issue and ships a regression test that **fails before the fix**.

## Task 1 — `clearMismatchedDesignedVoices` must skip cloned voices `[ADV-C1]`

**Files:** Modify `server/src/tts/verify-designed-voice-language.ts:41-48`; Test `server/src/tts/verify-designed-voice-language.test.ts`

**The bug, verified:** the loop has no provenance check and resolves the manifest via `qwenVoiceSidecarPath(qwenStorageKey(c, c.id))` → `qwen-<c.voiceUuid ?? c.voiceId ?? c.id>` (`voice-mapping.ts:21-26`). A cloned voice's manifest lives at `qwen-<libraryUuid>` (`voice-mapping.ts:341`), and the assign route never sets `c.voiceUuid` (`voice-library.ts:917-930`) — so the read **always** misses, `manifest` is null, and `delete c.overrideTtsVoices.qwen` removes the clone marker. Callers: `generation.ts:810`, `chapter-splice.ts:266`, both inside `if (nonEnglishBook)`.

**Repro:** clone a voice → assign to a character in a Russian book → Generate. The slot is deleted; `pickVoiceForEngine('qwen')` returns `''`; `needsFallback` fires; `forbidKokoroFallback` + `coquiEligible` (ru ∈ `ENGINE_LANGUAGE_SUPPORT.coqui`) routes to `pickVoiceForEngine('coqui', …)` = **a stock XTTS catalog voice.** Silent.

- [ ] **Step 2: Run to verify it fails** — the slot is deleted, character appears in `cleared`.
- [ ] **Step 3: Implement** — first line of the loop body:
```ts

       facts made this loop delete the clone marker on every non-English
```

## Task 6 — `CoquiEngine._synth_lock` `[AC-I4]`

**Files:** Modify `server/tts-sidecar/main.py` (`CoquiEngine`); Test `tests/test_concurrent_synthesis.py`

Qwen added `_synth_lock` because "the Base model isn't thread-safe" (`main.py:3799-3800`). 3c introduces a *second* concurrent entry point into the same `self._tts` object — `/xtts/clone-voice` calls `_ensure_loaded` + `get_conditioning_latents` + `inference` from an `asyncio.to_thread` worker, and `derive-engine-artifact.ts:52-56` issues a **bare `fetch` outside** `sidecar.ts`'s per-engine `CountSemaphore(1)` (`sidecar.ts:55-62,168,236`), so Node does not serialize it either. Without this lock a derive and a synth can mutate/read `self._tts` concurrently.

## Task 8 — Latents synth branch: fail loud, config-faithful, tombstone-safe `[AC-C3] [AC-C7] [AC-I1] [AC-I3] [ADV-M1]`

**Files:** Modify `server/tts-sidecar/main.py` (`CoquiEngine.synthesize`, 1262-1314); Test `tests/test_xtts_clone_voice.py`

**This is the correctness core.** Three separate requirements:

**(a) Placement.** The branch **must** precede the `self._speakers` membership check (`main.py:1275-1287`). `xtts-<uuid>` is never in the manifest, so falling through substitutes `FALLBACK_SPEAKER` and silently renders a stranger. `/synthesize` already maps `VoiceNotDesignedError` → **409** engine-agnostically (`main.py:7306-7319`), so raising needs no route change.

**(b) Config fidelity + text splitting `[AC-C3]`.** `inference()` called bare hardcodes `temperature=0.75`, `repetition_penalty=10.0`, `top_p=0.85` (`xtts.py:448-462`) instead of config, **and** defaults `enable_text_splitting=False` while the shipped `self._tts.tts(...)` path splits by default (`TTS/api.py:300`, `TTS/utils/synthesizer.py:330,368-369`). `inference` then asserts `text_tokens.shape[-1] < self.args.gpt_max_text_tokens` (`xtts.py:516`, ~400 tokens) — **so a long sentence that renders fine on a stock coqui voice hard-crashes on a cloned one.** Mirror `Xtts.synthesize`'s `inference_settings` dict and pass `enable_text_splitting=True`. Also mirror its `language in self.config.languages` check, which the low-level path skips (`xtts.py:423`).

**(c) Cache epoch — closes the revoke-during-load race `[AC-C7] [ADV-M1]`.** `purgeCloneArtifacts` is files-first / evict-last (`purge-clone-artifacts.ts:8-11`). Naive `read cache → isfile → torch.load (seconds) → write cache` lets a load already past `isfile` repopulate the cache **after** the evict landed, leaving a revoked person renderable from RAM until sidecar restart — exactly what §5.6 forbids. Fix: a monotonic `_evict_epoch` per voice, captured **before** `isfile` and re-compared under `_latents_lock` immediately **before** installing the entry; refuse the install if it moved.

- [ ] **Step 1: Write the failing tests**
  - cloned key renders via `inference` with `substituted_from is None`
  - missing latents raises `VoiceNotDesignedError`
  - **placebo-proof:** on missing latents, spy on **`_tts.tts`** (the real fallback path — asserting on `tts_model.*` can never observe a fallback `[AC-M1]`) and assert it was never called
  - a baked catalog voice still substitutes exactly as before (regression)
  - `inference` receives config-derived settings and `enable_text_splitting=True`
  - **interleaving:** simulate an evict landing mid-`torch.load`; assert the cache is **not** populated afterwards and the next synth raises
- [ ] **Step 2: Run to verify they fail.**
- [ ] **Step 3: Implement** `_load_voice_latents` + the branch. Function-local `import torch`; `torch.load(pt_path, map_location='cpu', weights_only=False)` — **`map_location` is required**: latents are saved as CUDA tensors on the deriving device (`xtts.py:361-370`), and on the dual-GPU box placement can derive on cuda:1 and synth on cuda:0. `inference` moves both to `self.device` anyway (`xtts.py:505-506`), so `'cpu'` is free `[AC-I1]`.
