# fs-38 Wave 3c — XTTS voice clone Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a cloned voice render on Coqui XTTS v2 as well as Qwen — and close the upstream defects that today let a cloned voice render as a stranger, or let a *revoked* person's voice keep playing.

**Architecture:** The clone identity lives in the voice-library entry (`master.wav` + consent). 3c adds a **second derivable artifact** — `voices/xtts/xtts-<uuid>.pt` (gpt conditioning latents + speaker embedding) — produced by `POST /xtts/clone-voice` from the same PCM the Qwen route consumes. Everything downstream becomes **engine-parametric**. Derivation is **lazy**: assignment writes both clone-capable slots, and whichever engine a chapter routes to gets its artifact derived by the 3b2 pre-pass — partitioned by engine so Qwen and Coqui are never forced co-resident.

**Tech Stack:** Python 3.12 sidecar (FastAPI, coqui-tts 0.27.5, torch), Node 20 + TypeScript server (Express, Vitest), React 18 + RTK frontend, Playwright e2e, pytest.

## Global Constraints

Every task's requirements implicitly include this section.

- **`TtsEngine` has no `'xtts'` value.** The engine is `'coqui'` (`server/src/tts/model-keys.ts:18`). `xtts` is **only** the manifest slot key `engines.xtts`, the artifact dir `voices/xtts/`, and the storage prefix `xtts-<uuid>`.
- **Property 1 — never-silent-substitution.** A cloned voice either renders as itself or fails loud. Never substituted — not by `FALLBACK_SPEAKER`, not by `applyQwenFallback`, not by the coqui profile catalog, **and not by having its marker deleted upstream** (Phase 0).
- **Property 2 — erasure is total.** On revoke, every artifact the voice can be *rebuilt or rendered from* is destroyed: disk artifacts, sidecar in-process caches, **and every audition cache regardless of its scope key** `[FAB-C1]`. Already-rendered chapter audio is out of scope by product decision — state that explicitly in plan 269 rather than leaving "total" unqualified `[FAB-M4]`.
- **`provenance` decides the FAILURE POLICY, and it is never inferred from a name prefix.** `qwenStorageKey` returns `qwen-<uuid>` for **designed** voices too (`voice-mapping.ts:21-26`), so a `qwen-` prefix test is *not* a cloned test `[EX-8]`. Both `cloned` and `designed` entries can carry a coqui slot (D-B/D-E); what differs is what happens when the artifact is missing:
  - **`cloned` ⇒ fail loud.** Never substituted, never fallen back, on any engine. This is Property 1.
  - **`designed` ⇒ fail soft.** Fall back to `COQUI_PROFILE_VOICES` exactly as today. Never a new hard failure (§2.3).
  - **`imported`, or `designed` with no `master`** ⇒ no coqui slot is ever written; behaviour is byte-for-byte unchanged.
  Any new branch must state which policy it is on. A branch that treats the two alike is wrong in one direction or the other.
- **Shared vocabulary lives in `server/src/tts/clone-engines.ts`** (Task 1). Never redefine `CloneEngine`, `CLONE_CAPABLE_ENGINES`, `manifestSlotFor`, or `characterHasClonedSlot` locally — four tasks would otherwise write four copies, each passing its own review `[EX-11]`.
- **OpenAPI is the type source of truth.** `VoiceLibraryEngines.xtts` exists at `openapi.yaml:5087-5093` with `coquiVersion` + `modelId`. Any wire change (including Task 24's engine-aware sample request `[FAB-M3]`) means editing `openapi.yaml` then `npm run openapi:types`. **Never hand-edit `src/lib/api-types.ts`.** `server/src/workspace/voice-library.ts:23-33` is a manual mirror — keep names identical.
- **User-facing copy says "Coqui XTTS v2"**; the blessed short label is **`Coqui`** (`src/lib/tts-models.ts:146-152`). Never bare "XTTS" in UI copy, including status chips `[AC-I8]`.
- **No hex colour literals.** **Touch targets ≥44×44** via `min-h-[44px] fine-pointer:min-h-0` (never `sm:min-h-0`).
- Behind `voices.library.enabled` (`server/src/config/registry.ts:644-653`). `XTTS_VOICES_DIR` is a derived spawn env like `QWEN_VOICES_DIR` — no registry knob. Any *other* new env var needs one.
- **Test commands.** Server: `npm --prefix server run test` or `cd server && npx vitest run <path>`. **There is no `src/tts/` at repo root** — root `npm test` is the frontend suite `[EX-2]`. Sidecar: `server/tts-sidecar/.venv/Scripts/python.exe -m pytest server/tts-sidecar/tests/<file> -v`.
- **Sidecar tests run without GPU or weights.** Use `sys.modules` injection (`tests/test_runtime_wiring.py:53-190`) or fixture reuse (`tests/test_qwen_clone_voice.py:1-31`). Use **bare `TestClient(main.app)`**, never `with TestClient(...)` — the context manager fires six startup handlers against the fake torch `[AC-I5]`.
- **`vi.resetModules()` footgun:** never assert `instanceof` on a statically-imported class in a file calling `vi.resetModules()`.
- **Report what you observed.** If a step SKIPs (missing weights, missing browser), say so with the reason. Never report an unobserved pass `[EX-17]`.

## Design decisions

| # | Decision | Spec said | Why |
|---|---|---|---|
| **D-A** | **No engine picker in the clone wizard.** Clone derives Qwen first; XTTS derives lazily when a chapter routes to coqui. | §6: "Phase 2 (3b1, **+engine choice 3c**)". | §4.2 already says `deriveEngineArtifact` "serves engine-switch + orphan self-heal". A picker asks the user to commit to an engine they cannot evaluate yet. **Verified sound by all four passes.** |
| **D-B** *(reversed — user call)* | **Designed-voice XTTS eligibility IS in scope**, with a **fail-soft** policy that is the exact opposite of the cloned one. | Wave table: "spike-gated"; §2.3 calls synthetic-clip→latents "quality-unvalidated". | Delivered in-wave at the user's direction. The quality question is real but the **downside is bounded**: a designed voice on a Coqui book renders an *unrelated stock catalogue speaker* today, so even an imperfect derive from its own calibration clip is closer to the intended identity than the status quo. See **D-F** for the policy that keeps it safe. |
| **D-F** *(new — required by D-B)* | **Failure policy differs by provenance.** Cloned → fail loud, always. Designed → **fall back to the catalogue**, never hard-fail. Designed entries with **no `master.wav`** (pre-§2.3 legacy, spec §9) get **no coqui slot at all** and keep today's behaviour byte-for-byte. | §2.3: the designed clip-persist work "never introduces a new hard failure". | Without this, D-B re-creates exactly the Critical that review caught in D-E's first form — a designed voice pointed at an XTTS key with nothing behind it, hard-409ing mid-chapter where it renders fine today. A designed voice is not a real person's identity; substituting it is the *current, acceptable* behaviour. A cloned voice is, and must not be. |
| **D-C** | **Hand-rolled latents** (`get_conditioning_latents` + `_atomic_torch_save`), not `CloningMixin`. | Not addressed. | Verified: the built-in slugifies and writes `<voice_dir>/<slug>.pth` via plain `torch.save` (`TTS/utils/voices.py:100-113`) — we would not control the path (so purge could not reliably erase) and the write is not atomic. |
| **D-D** | **Sidecar substitution of a cloned key is FATAL Node-side** — gated on `xtts-` only, plus provenance. | Not addressed. | `sidecar.ts:188-195` only warns. Gating on `qwen-` too would make *designed* substitution fatal, which the Global Constraint forbids `[EX-8]`. |
| **D-E** *(amended twice)* | **Assign writes both clone-capable slots when the entry can actually render on both** — i.e. `provenance === 'cloned'`, **or** `provenance === 'designed'` **and** `entry.master` exists. Never for a designed entry with no `master`. | Not addressed. | A qwen-only slot means an engine switch drops to `COQUI_PROFILE_VOICES` and silently replaces a real person. **The unconditional form was Critical** — a designed entry got `xtts-<uuid>` with no latents and hard-409'd mid-chapter `[AC-C5][ADV-H3]`. The `master`-exists condition is what makes D-B safe: the slot is only written when there is something to derive from, and D-F governs what happens if that derive still fails. |
