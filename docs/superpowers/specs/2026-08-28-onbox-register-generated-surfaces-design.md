# On-box register: generated derived figures, reconciled row shells, and the end of the drift-detector family

**Issues:** closes [#2362](https://github.com/dudarenok-maker/Castwright/issues/2362),
[#2708](https://github.com/dudarenok-maker/Castwright/issues/2708),
[#2721](https://github.com/dudarenok-maker/Castwright/issues/2721); completes
[#2599](https://github.com/dudarenok-maker/Castwright/issues/2599) and
[#2603](https://github.com/dudarenok-maker/Castwright/issues/2603) via the held
tasks of the preceding plan.

**Predecessor:** [`2026-08-27-onbox-register-stable-row-ids-design.md`](2026-08-27-onbox-register-stable-row-ids-design.md).
That spec fixed row-ID *renumbering*. This one fixes the surface duplication that
renumbering was only one symptom of.

> **Revision note.** This spec's first draft was rewritten after its
> `assumption-checker` pass. Four of its claims were falsified by measurement and
> are corrected in place rather than quietly dropped: the enforcement path (it
> modelled one gate; there are two, and the unmodelled one is required), the
> generated-element inventory (the per-group `gcount` spans were generated by
> nothing while their detector was deleted), the character of the six
> `unknownSubject` residuals (four are checker artefacts, not stale citations),
> and A1's size (341 lines, not the ~570 first claimed). The design below is the
> post-review one. **The governing lesson, applied throughout: generate figures,
> never prose.**

## Problem

### The family reproduces because the register has two hand-maintained copies of the same facts

Seven issues have now been filed about `docs/testing/onbox-acceptance-register.md`
and its published twin. Five are closed; each closure orphaned something:

- **#2629** (citation rot) shipped, and its closure orphaned **#2721**.
- **#2634** and **#2653** were the same duplicate-row-ID finding, filed three weeks
  apart by two different reviews.
- **#2599** was closed by declining the row-content diff it asked for — which
  leaves **#2362**, open since before it, as the surviving home for that question.
- **#2603** was closed without its title-match option and without self-reference
  detection.
- **#2708** is a fresh policy question about a changelog that exists twice.

The predecessor spec named the mechanism behind four of them: a checker that
*required* row IDs to be contiguous, so every discharge forced a renumber of
roughly 210–225 citations across ~65 files. That is fixed — IDs now allocate once,
above a floor of 101, and are never reused.

**But the family did not stop.** #2362, #2708 and #2721 all postdate or survive
that fix, because renumbering was a symptom of a deeper property: **the register's
derived figures exist twice, in two files, both maintained by hand.**

Every ticket in this family is a *detector* for drift between those two copies.
Detectors compose, and each new detector raises a fresh boundary question — what
counts as a citation, what is fatal, what is benign, what does "agreement" mean.
Each boundary question is itself a decision, and each decision becomes a ticket.
That is the replication engine, and no additional detector switches it off.

### The two incidents that define the class

**#2362 — the surfaces stated contradictory facts and CI was green.** PR #2359
corrected the same wrong sentence three times across two review passes. Pass 3
found the register still saying the Coalfall family is "five language editions"
while its published twin had already been corrected to "seven". For one commit the
tracked pair asserted **different facts in the same clause**, and
`npm run check:onbox-register` passed throughout.

**#2599 — a published page silently regressed and the mandated comparator said OK.**
During PR #2578 round 18 another session reverted the published artifact to a stale
version of a row's body. `check:onbox-register -- --against-published <page>`
returned `OK` because the row count and the row ID both still matched — only the
body text had regressed.

### What is duplicated today, measured

Every one of these is a **figure**, and every figure is derivable from the `.md`.

| Figure | Lives in `.md` | Lives in `.html` | Generated here? |
|---|---|---|---|
| Owed total | `:431` | strip tile `:198` | yes — `strip` |
| Groups / Blocked / Unconfirmed counts | glance table `:419-430` | strip tiles `:199-202` | yes — `strip` |
| Oldest debt | `:431-433` | strip tile `:203` | yes — `strip` |

| Row ID set and order | 65 `###` row headings | 67 `details.item` shells | yes — shell reconciliation |

The changelog row is the live failure. The page admits it at `:265-269`: those
entries *"predate wave 7 and are historical only"* because the callout box *"was
not kept current across those waves"*. Six of the other seven agree **because
people keep checking them by hand**.

**The nine `gcount` spans are the finding that reshaped this spec.** They live at
`.html:361, 917, 958, 1251, 1283, 1410, 1451, 1485, 1530`, inside each group's
`h3.gtitle`. The first draft generated three regions, none of which contained them,
and simultaneously deleted their only detector (`check-onbox-register.mjs:941-945`).
That would have left a duplicated figure with no generator and no check — the exact
defect this spec exists to remove, reintroduced by it. **The deletion list must be
derived from an inventory of generated elements, never from what looks generated.**

## The constraint that shapes everything: the live view is an editorial summary

Generating the live view's row *bodies* from the markdown is not buildable:

| | register `.md` | live view `.html` |
|---|---|---|
| Total lines | **4,539** | **1,554** |
| Longest row (A1) | **341 lines** (`:691-1031`) | a handful of summary blocks |

The HTML does not excerpt the markdown — it **rewrites** it. Compare E1's source
(`.md:3574-3634`) with its rendering (`.html:1287-1297`): sentences are shortened,
reordered and reworded, deliberately.

**The HTML also carries prose that exists nowhere in the markdown**, and this is
what forces "figures, never prose":

- the per-row `risk` / `risk low` / `risk hot` synopsis in each summary (A1's reads
  `20 of 60 run · ~40 owed · 3 retracted`);
- the `iname` span — a shortened title with markdown links stripped;
- **the group header titles**: `.html:361` reads `The GPU box` where `.md:421`
  reads `The GPU box (single 8 GB for most; the 2-card boot for a few)`. Five of
  seven differ this way;
- **`lang="ru"` accessibility spans** wrapping `Ночной дозор` at `.html:958` and
  `:347`, with no markdown counterpart. The first draft's instruction to copy the
  glance cells "verbatim" would have **deleted this attribute** — a real
  accessibility regression shipped by an anti-regression tool.

And the markdown's rows have no schema: `*Needs:*`, `*Criteria:*` and `*Cost:*`
recur but are optional, interchangeable with `*Hardware:*`, and often collapsed
onto one line; long rows invent their own subheads per row.

So generating row bodies has exactly two implementations, and both are wrong:
emit the markdown's prose (the page stops being the readable operator page), or
write an abstractive summariser (not a build step).

**The prose is not the drift class.** #2362 was a *number*. #2599 was a body
regressing while its *ID and count* held. #2708 is a changelog of *counts*.

## Designs this spec rejects

**Rejected: generate the row bodies (#2362 option 3 as literally written).**
Falsified by the 4,539-vs-1,554 ratio and the four HTML-only prose fields above.
Option 3 says to generate what "both files share" — they share figures, not prose.

**Rejected: generate any prose cell, including the glance table's Setup column and
the group header titles.** Five of seven differ from their markdown source by
deliberate editorial shortening, and one carries `lang="ru"`. Generation would
overwrite hand-authored, published content. **Only the count column and the
`gcount` spans are generated; the descriptions beside them are preserved.**

**Rejected: whole-page generation.** Discards the style block (`:35-158`), the
`risk` synopses, the shortened titles and the jump links — none of which exist in
the markdown. Re-adding them means inventing a row schema for a document whose rows
are demonstrably ad-hoc.

**Rejected: stop tracking the `.html`.** All four recorded wrong-file publishes
(2026-07-31 → 08-01) and the #1931 concurrency incident were caught by a human
looking at the tracked file.

**Rejected: a pre-commit hook that regenerates silently.** Silent rewrites during
commit are unreviewable. Note this rejection is *not* on scope-gating grounds: the
existing checks already run there, because `verify-cache.mjs:199-201` lists both
register files as `test:hooks` `extraFiles` precisely so a register-only diff
cannot print `[cached]`.

**Rejected: a declared shared-facts block per row (#2362 option 2).** Its weakness
is named in #2362's own body — it *only protects claims someone remembered to
declare*. **Not rejected forever**: if a second "five vs seven" incident occurs
after this ships, this is the next move.

## Design

### 1. The generator is a reconciler, not a renderer

`scripts/build-register-live-view.mjs`, run as `npm run register:build`.

**Inputs:** the register `.md` **and the current** live-view `.html`.
**Output:** the same `.html`, with derived figures rewritten and row shells
reconciled, and **every hand-authored byte outside a generated target preserved**.

Taking the current `.html` as an input is what makes an editorial page compatible
with a build step. A pure renderer would have to invent the prose it cannot derive.

**Its coverage boundary, stated because it is invisible otherwise:** `--check`
compares a regeneration against the committed file, so its reach is exactly
*{generated targets} ∪ {row-shell structure}*. Everything else round-trips
byte-identically and is **uncheckable by construction**. This is why §5's deletion
list is derived from the inventory in §2, not from inspection.

It is hand-rolled string manipulation, matching every other parser in `scripts/`
— the repo has no markdown or HTML library. That precedent covers *targeted
replacement* (`stamp-publish-token.mjs` is 188 lines rewriting one hidden div); it
does **not** cover reordering elements or byte-exact idempotence, which are new
and are why §"Testing" leads with them.

### 2. Four generated targets — figures only

Region-style targets are delimited by `BEGIN GENERATED:<name>` / `END GENERATED:<name>`
HTML comments. Two targets are too scattered for regions and are located
structurally instead.

**`strip` (region)** — the six stat tiles at `.html:197-204`, replaced wholesale,
labels included. Sources: the `.md` glance table (`:419-430`), the owed line
(`:431-433`), and **two declared markers** for the A1 tile.

> **The A1 tile carries two facts, not one.** `.html:202` reads
> `Still owed in A1 (of 60)` with value `40`. A1's heading (`.md:691`) reads
> `20 of 60 run … · ~40 still owed`: the `40` is A1's still-owed count and the
> `60` is **A1's own sub-item total** — which merely *coincides* with the
> register's 60 owed rows today. The changelog shows the owed total moving through
> fifteen values in two weeks, so a generator templating `(of {owedTotal})` is
> right now and wrong at the next discharge. Two markers are declared beside the
> heading: `stat:a1-still-owed` and `stat:a1-subtotal`.

**`glance` (region, count column only)** — the count cell of each glance-table row
at `.html:345-351`. **The Setup description cells and the jump links are outside
the markers and are never touched.** The `.html` glance table has seven rows and no
Blocked/Unconfirmed rows; those two counts live in the strip tiles, and the first
draft's claim that this region includes them was wrong.

**`groups` (structural)** — the text of each `span.gcount` (`N rows`), located by
its enclosing `section[id]`. Nine targets, one per section, including `blocked`
(5 rows) and `unconfirmed` (2 rows). **The surrounding `h3.gtitle` prose and the
`gtag` badge are not touched.**

**`changelog` (region)** — the callouts at `.html:206, 272, 286, 297, 307, 322, 331`,
from the `.md` blockquote at `:435-678`. **All fourteen entries render**,
most-recent first. The general "How this register goes stale" callout at `.html:188`
is not a changelog entry and stays outside the markers.

> **The `.md` changelog's grammar is not uniform.** Entry 14 absorbs two further
> history items as inline `Before that:` prose (`:670`, `:675`) that a
> `^> \*\*(Last|Prior) change:` parser will not see as entries. The parser must
> handle both shapes, and a line matching neither is an **error**, not a skip.

This is what settles **#2708**: the choice between "keep and curate" and "drop and
point at git" dissolves, because the curated copy stops being a copy.

> **#2708 is only closed if the source is checked too.** Generation makes the
> mirror *faithful*, not the source *true* — and today **nothing validates the
> `.md` changelog at all** (`check-onbox-register.mjs` contains no reference to
> it). So one check ships with the generator: **the newest changelog entry's
> terminal count must equal the owed total** at `:431`. Without it, #2708's stated
> requirement — *needs a mechanical check, or the staleness recurs* — is met one
> level up and left open one level down.

### 3. Row shells are reconciled; bodies and summaries are never touched

Sections are located by **`id`**, never by class: `ga`, `gb`, `gc`, `gd`, `ge`,
`gg`, `gh`, `blocked`, `unconfirmed`. There are **nine** `section` elements
carrying class `group`, not seven, and `is-soft` is shared by Group H and
Unconfirmed — so class cannot discriminate an ID'd section from a positional one.

For the seven ID'd sections, every `### <ID> · <title>` heading in the `.md` must
have a matching `details.item`, in the markdown's order. The generator **inserts**
a shell for a new ID, **deletes** a shell whose ID has left (a discharge),
**reorders** shells to match, and **preserves verbatim** every surviving shell's
body div, `iname` span and `risk` span.

One non-row `###` heading must be excluded: `.md:51` ("The publish token") sits
inside the Live-view section.

**Blocked and Unconfirmed are matched by title, not by position.** Both render as
`details.item` with `<span class="num">—</span>` (`.html:1489, 1497, 1534, 1542`),
so the element gives no identity, and Unconfirmed's source is plain bullets
(`.md:4514, 4519`), not headings. Positional matching has no identity at all:
reorder two entries and the reconciler silently re-attaches each body to the other,
which is unobservable in review and untestable by any assertion about counts.
Title matching is also **the register's own recorded rule** — `.md:494` instructs
readers to *"cite them by title from now on"* — and today's titles prefix-match
their `iname`s. A title that matches zero or more than one shell is an **error**.

**A committed placeholder fails `--check`.** A newly inserted shell carries
`<p class="body-placeholder">`. `--check` fails if that class appears anywhere in
the committed file — so the failure does not depend on whether the author ran
`register:build`, which is the hole the first draft left. This converts "row added
to the `.md`, forgotten in the `.html`" — the #1931 class — into a failing gate.

### 4. Enforcement: parity first, byte-comparison second

**The bar is parity with what is deleted, and the first draft failed it.** Today
`.md`↔`.html` agreement is enforced in **two** places, not one:

1. `.github/workflows/onbox-register-check.yml` — path-filtered, and **not** a
   required status check (it says so at its own `:5-7`).
2. `scripts/tests/check-onbox-register.test.mjs:1181`, which asserts
   `checkLiveView(md, lv)` is empty **against the real committed files**, under
   `test:hooks` — which runs in pre-commit `verify:fast:scoped`, pre-push
   `verify:fast:branch`, `test:all`, **and `verify.yml`, a required check on
   `main`**. `verify-cache.mjs:199-201` lists both register files as `extraFiles`
   specifically so a register-only diff cannot skip it.

So `register:build -- --check` is wired into **both**:

- **`test:hooks`** — `scripts/tests/build-register-live-view.test.mjs` runs
  `--check` against the real files, exactly as `:1181` does today. This preserves
  the required-check enforcement, and it is the reason `:1181` can be retired
  without loss rather than left behind as a near-vacuous assertion.
- **`onbox-register-check.yml`**, whose path filter gains
  `scripts/build-register-live-view.mjs`.

**Line endings must be handled before byte-comparison is safe.** `.gitattributes`
pins `*.mjs`, `*.sh`, `openapi.yaml` and others to `eol=lf`, each after a recorded
incident (#1952, #2586, #2588) — but **`*.md` and `*.html` are unpinned**. This box
has `core.autocrlf=false` so the working tree is LF and the hazard is invisible
here; on a checkout with Git-for-Windows' default `autocrlf=true`, `--check` would
fail on every line and `register:build` would rewrite all 1,554 lines to LF.
`checkLiveView` was **deliberately made CRLF-tolerant** (`:1182-1185`), and a naive
byte-compare discards that. Two things ship together:

1. `*.md` and `*.html` are pinned `eol=lf` in `.gitattributes` (PR 1). Note that
   file's own recorded limitation: **a pin does not self-heal an existing
   checkout.**
2. The comparator normalises line endings via the existing
   `scripts/lib/read-normalized.mjs` before comparing, so an already-CRLF checkout
   degrades to a correct pass rather than a 1,554-line false failure.

**Idempotence is a hard requirement and a tested one.** `build` then `build` is a
no-op; `build` then `--check` passes. A reconciler that is not idempotent silently
rewrites hand-authored prose on its second run.

### 5. What retires from `check-onbox-register.mjs`

Each deletion below is justified by a **named generated target from §2** — not by
inspection.

| Check | Lines | Replaced by | Disposition |
|---|---|---|---|
| Owed total, `.md` vs `.html` | `:792-805` | `strip` | **delete** |
| Glance per-group counts | `:852-856` | `glance` | **delete** |
| Section header counts (`gcount`) | `:941-945` | `groups` | **delete** |
| Row-ID set, expected vs found | `:946-949` | shell reconciliation | **delete** for `'both'`; **retained** for `extraOnly` |
| `checkRegister` — the `.md`'s own arithmetic, 4a uniqueness, 4b allocation floor | — | — | **retained in full** — the `.md` is the source and is hand-maintained |

**`--against-published` survives untouched.** It compares the working tree against
the **live published page**, which no generator can constrain — a competing lane's
publish is an external event. Its `extraOnly` direction, the `staleExtra` /
`origin/main` baseline filter (`:984-998`), `--discharging` (`:1269`) and the
publish-token ancestry check all remain.

`check-onbox-register.test.mjs:1181` is **replaced, not deleted** — its real-file
assertion moves to the new test file as a `--check` run, so the required-check
coverage transfers in the same PR that removes it. Leaving it in place would land
a near-vacuous assertion inside the PR that made it vacuous.

### 6. `wrongId` becomes fatal for the discharge class (#2721)

The decision is taken — **widen it**. Under allocate-once IDs a discharged row's ID
is retired permanently, so a citation to it is unambiguously dangling rather than
silently re-pointing at whatever inherited the number.

**But the issue's premise is wrong twice, and the fix has a prerequisite.**

*First*, the "rehome" half is already done, and the spec's own first draft named
the wrong sites. The three real ones are `check-register-citations.mjs:37` (which
defers the **Task 12 workflow**, not `wrongId`), `check-register-citations.mjs:210`
(the `wrongId` deferral itself), and **`register.md:388`** — not `:501-503`, which
is about #2629's contiguity check and contains no `#2721` at all.

*Second*, the six `unknownSubject` residuals are **not six stale citations**. The
count is right; the characterisation is not. `buildLegitimateSubjectMap` builds its
subject map from **row headings only**, and four of the six fire for that reason:

- `onbox-sitting-two-card-boot.md:86` cites `A3` for `#1230`. A3 **is** that
  subject — the number sits in A3's **body** (`register.md:1059`), not its heading.
  **This citation is correct.**
- `onbox-sitting-cloning-identity.md:237` and `:308` cite `#2316` and `#2398`,
  which are **PR numbers**; the lines' real subject (`#2310`) is in A32's heading.
- `onbox-sitting-vram-contention.md:95` and `:248` already carry
  `> **Register row: A19 — discharged … row removed from the register**` on the
  next line — the repo's own annotation convention, which Check A honours 23 times
  in the same run.

**So widening `wrongId` to fatal without fixing the subject map would make a
correct citation permanently red** — precisely the false positive `:210` deferred
on. Three things ship in order:

1. **Fix `buildLegitimateSubjectMap` first**: read row **bodies** as well as
   headings, and distinguish issue numbers from PR numbers. This is the
   prerequisite, and it is where the paired tests go.
2. **Re-measure the residuals** against the fixed map. Only what still fires is a
   real stale citation, and only those are corrected.
3. **Then widen** `wrongId` to the discharge class, and rewrite the three deferral
   sites to state the shipped behaviour.

The subtlety recorded in #2721 still holds: the subject map is one-to-**many**, so
discharging one row of a multi-row subject does not remove the subject. The
widening keys on the subject leaving entirely, not on one ID leaving.

### 7. The two held tasks from the predecessor plan

- **Task 10** — wire the publish-nonce ancestry comparator into
  `--against-published`. The data half shipped in PR #2740. The comparator consumes
  **four** history answers and `nonceInHistory` takes **five** arguments; the
  predecessor plan declares one and four, and is corrected in place. Its embedded
  implementation was design 6, killed in review — the shipped module is the
  reference, not that code block.
- **Task 12** — stand `check-register-citations.mjs` up as its own workflow. It
  scans the whole tracked tree (3,493 files) but **no workflow references it**; its
  only trigger is `test:hooks`, diff-gated to `docs/testing/**`, `scripts/**` and
  `CLAUDE.md`. This is what makes #2603's closure honest.

## What this does NOT cover

**Prose drift is not detected.** A row's rewritten body, its `iname`, its `risk`
synopsis and the group header titles can all diverge from the markdown and nothing
will catch it. This is the deliberate price of keeping the page readable, and it is
the residual #2362 identified. The trigger for revisiting it is a second "five vs
seven" incident, and the next move is the shared-facts block rejected above.

**Self-reference is still undetectable.** The register and its live view are in
`check-register-citations.mjs`'s `FROZEN_EXACT` (`:382-390`) by design, so a row
body citing its own ID is never scanned.

**Publishing stays manual.** CI has no credentials to fetch the artifact. The
four-step runbook, the canonical artifact URL and the pinned favicon are untouched.

## Delivery

Four PRs. The split is forced by the rule the predecessor spec learned the hard way
— **anything a checker requires of `origin/main` must be on `main` before the code
that requires it** — and by the fact that PR 3 changes published content.

**PR 1 — data and pins.** Insert the marker pairs, add the two A1 markers to the
`.md`, and pin `*.md` / `*.html` to `eol=lf` in `.gitattributes`. No generator, no
checker change.

**PR 2 — the subject map.** Fix `buildLegitimateSubjectMap` to read bodies and
distinguish PR from issue numbers; re-measure the residuals; correct whichever
survive. Independent of the generator and small enough to review on its own.

**PR 3 — the generator and the retirement.** `build-register-live-view.mjs`,
`npm run register:build` / `--check`, both wirings (`test:hooks` and the workflow),
and §5's deletions with `:1181`'s coverage transferred. `refactor` scope, so `high`
review depth.

> **PR 3 changes the published page and must say so.** The first `register:build`
> renders 14 changelog entries where 7 stand today, growing the page by roughly
> 130 lines. That is a visible content change to a page an operator reads — it is
> declared in the PR body, reviewed as content, and published in that PR.

**PR 4 — `wrongId` and the held tasks.** The widening (now safe, given PR 2), the
three deferral-site rewrites, Task 10 and Task 12.

**Sequencing hazard, external to this chain.** The `#2759` sweep (children
`#2760`–`#2769`) includes `#2768`, an on-box acceptance item whose verify PR would
edit both register files. Two lanes editing the register concurrently is the #1931
class this spec exists to end. **These chains run in sequence, not in parallel.**

## Testing

`scripts/tests/build-register-live-view.test.mjs`, fixturing its own register and
live-view text (following `check-onbox-register.test.mjs`'s `buildRegister` /
`buildLiveView` pattern at `:45-79` and `:979`), plus the real-file `--check` run
that inherits `:1181`'s role:

- **`build` then `build` is a no-op**, and `build` then `--check` passes —
  idempotence, red before, and the property everything else depends on;
- a changed owed total rewrites only the `strip` region — **assert the style block,
  every row body, every `iname`, every `risk` span, every glance Setup cell and
  every `h3.gtitle` are byte-identical**, including the `lang="ru"` spans at
  `:347` and `:958`. This is the anti-regression test for the first draft's
  "verbatim copy" defect;
- a changed group count rewrites that group's `gcount` span **and its glance count
  cell**, and nothing else — the `groups`/`glance` pair the first draft omitted;
- the A1 tile renders from its two markers, and **changing the register's owed
  total does not change the tile's `(of N)`** — the coincidence trap;
- a row added to the `.md` inserts a shell **with the placeholder**, in the right
  section, in markdown order; and **a committed placeholder fails `--check`**;
